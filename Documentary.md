# MovieAndroid — TMDB Explorer

## 1. Project Name

**MovieAndroid — TMDB Explorer**

Мобильное Android-приложение для поиска, просмотра и сохранения информации о фильмах. Проект разработан командой **Chicken Nuggets** в рамках дисциплины ПМВС.

---

## 2. Description

MovieAndroid — это Android-приложение, позволяющее пользователю просматривать фильмы, искать их по названию, открывать подробную информацию о фильме и добавлять фильмы в избранное.

Приложение использует внешний API для получения данных о фильмах и локальную базу данных Room для хранения избранных фильмов. Интерфейс реализован с использованием Jetpack Compose. Архитектура проекта построена по MVVM-подходу.

Проект демонстрирует работу с многооконным интерфейсом, touch-интерфейсом, локальным хранением данных, многопоточностью, внешним API, GitHub Actions и автоматическими тестами.

---

## 3. Основная функциональность

Приложение предоставляет пользователю следующие возможности:

- просмотр списка жанров фильмов;
- просмотр списка фильмов по выбранному жанру;
- поиск фильмов по названию;
- просмотр подробной информации о фильме;
- добавление фильма в избранное;
- удаление фильма из избранного;
- локальное хранение избранных фильмов;
- настройка языка интерфейса;
- настройка темы приложения;
- настройка масштаба текста;
- добавление пользовательских тегов и оценок;
- получение рекомендаций через AI-чат;
- использование Android App Widget;
- открытие карточки фильма через deep link;
- получение напоминаний о премьерах.

## 8. Архитектура проекта

Проект построен по архитектурному подходу MVVM.

Основные слои приложения:

```text
UI → ViewModel → Repository → Data Source
```

### 8.1. UI-слой

UI-слой реализован с использованием Jetpack Compose.

Он отвечает за:

- отображение экранов;
- обработку пользовательских действий;
- навигацию между экранами;
- отображение состояния загрузки;
- отображение ошибок;
- отображение данных, полученных из ViewModel.

### 8.2. ViewModel-слой

ViewModel отвечает за:

- хранение состояния экрана;
- обработку действий пользователя;
- вызов методов репозитория;
- подготовку данных для UI;
- работу с Kotlin Coroutines и StateFlow.

### 8.3. Repository-слой

Репозитории отвечают за получение и сохранение данных.

Источники данных:

- внешний API;
- локальная база данных Room;
- SharedPreferences.

### 8.4. Data-слой

Data-слой включает:

- сетевые API-интерфейсы Retrofit;
- Room Entity;
- Room DAO;
- Room Database;
- классы для работы с настройками;
- модели данных.

## 12. Схема базы данных

В приложении используется локальная база данных Room.

### 12.1. База данных

| Параметр | Значение |
|---|---|
| Имя базы данных | `movie_database` |
| Версия | `2` |
| Основная таблица | `favorite_movies` |

### 12.2. Таблица `favorite_movies`

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | ID фильма |
| `title` | TEXT | Название фильма |
| `overview` | TEXT | Описание фильма |
| `voteAverage` | REAL | Средняя оценка фильма |
| `posterPath` | TEXT | Путь к постеру |
| `backdropPath` | TEXT | Путь к фоновому изображению |
| `releaseDate` | TEXT | Дата выхода |
| `runtime` | INTEGER | Длительность фильма |
| `tagline` | TEXT | Слоган фильма |
| `imdbId` | TEXT | ID фильма на IMDb |
| `genresJson` | TEXT | Жанры фильма в JSON-формате |
| `tag` | TEXT | Пользовательский тег |

### 12.3. SQL-схема

```sql
CREATE TABLE IF NOT EXISTS favorite_movies (
    id INTEGER NOT NULL PRIMARY KEY,
    title TEXT NOT NULL,
    overview TEXT NOT NULL,
    voteAverage REAL NOT NULL,
    posterPath TEXT,
    backdropPath TEXT,
    releaseDate TEXT NOT NULL DEFAULT '',
    runtime INTEGER NOT NULL DEFAULT 0,
    tagline TEXT NOT NULL DEFAULT '',
    imdbId TEXT NOT NULL DEFAULT '',
    genresJson TEXT NOT NULL DEFAULT '[]',
    tag TEXT
);
```

### 12.4. DAO-операции

| Метод | Назначение |
|---|---|
| `getAllFavorites()` | Получить список избранных фильмов |
| `getMoviesByTag(tag)` | Получить фильмы по тегу |
| `insertMovie(movie)` | Добавить или обновить фильм |
| `deleteMovieById(id)` | Удалить фильм из избранного |
| `getMovieById(id)` | Получить фильм по ID |
| `updateTag(id, tag)` | Обновить тег фильма |

### 12.5. SharedPreferences

Кроме Room, приложение использует SharedPreferences для хранения пользовательских настроек.

| Ключ | Назначение |
|---|---|
| `language` | Выбранный язык интерфейса |
| `textScale` | Масштаб текста |
| `theme` | Тема приложения |
| `favorites` | Список ID избранных фильмов |
| `tag_<id>` | Тег конкретного фильма |
| `rating_<id>` | Пользовательская оценка фильма |

## 14. GitHub Actions и тестирование

Для проекта используется непрерывная интеграция GitHub Actions.

Workflow должен выполнять:

1. получение кода из репозитория;
2. установку JDK 17;
3. настройку Android SDK;
4. запуск unit-тестов;
5. сборку debug APK;
6. сборку androidTest APK;
7. запуск UI-тестов через Firebase Test Lab;
8. сохранение APK-файла как artifact.

### 14.1. Unit-тесты

Команда запуска unit-тестов:

```bash
./gradlew :app:testDebugUnitTest
```

### 14.2. UI-тесты

Команда локального запуска UI-тестов:

```bash

```

### 14.3. Firebase Test Lab

Для запуска UI-тестов в Firebase Test Lab используются:

- debug APK приложения;
- androidTest APK;
- Firebase project id;
- service account key.

Пример команды:

```bash
gcloud firebase test android run \
  --type instrumentation \
  --app app/build/outputs/apk/debug/app-debug.apk \
  --test app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk \
  --device model=Pixel2,version=30,locale=en,orientation=portrait
```

### 14.4. APK artifact

После успешного прохождения тестов GitHub Actions должен сохранять APK-файл приложения как artifact.
